Chapter 01May to Jul 2025AlgoUniversity · YC-backed

Ten weeks to build a judge that runs strangers' code.

AlgoUniversity picked its co-op cohort from 40,000+ applicants, and I landed in the top 1.4%. The brief was production-focused: design, build and deploy something real. I built Code Slayer, an online judge, on my own.

The problem

Every submission is untrusted.

An online judge executes code written by people you have never met. Each submission is C++ or Python, and any one of them can loop forever, eat all the memory, or simply fail to compile.

The call

Hard limits, no exceptions.

Each submission runs in a sandbox with 1,000 ms of time and 256 MB of memory. Go past either and the judge answers TLE or MLE; fail to compile and it answers CE.

Around the engine: JWT auth with role-based access, a rate limiter on the submission API to shut down abuse, and a Gemini code reviewer that handles three review scenarios.

What held

50+ active users, 500+ submissions.

The submissions came in during its first month. Judging and the web app ran as two services, on AWS EC2 with images in ECR and on Render, and verdicts came back in under 200 ms end to end. Three features cleared code review and shipped inside their sprints. The project is archived now, and the code is public.

Chapter 02Jul to Dec 2025Slayyers · Quick fashion delivery

A sixty-minute promise, in someone else's production.

Slayyers delivers fashion in 60 minutes. I joined as a software engineer intern and owned backend APIs, caching infrastructure and CI/CD. This time the users were paying customers.

The problem

The clock starts at checkout.

A 60-minute delivery window leaves no room for a slow API. Checkout, order tracking and routing all sit between a tap on a phone and a parcel at a door.

The call

Separate services, cached reads.

I built the platform's core flows as RESTful microservices, each deployed to production independently: the Try-First-Buy-Later checkout, real-time order tracking, and the logistics routing pipeline.

I designed the MongoDB and PostgreSQL schemas behind them, deployed the services on AWS, and added Redis caching.

What held

API latency down by more than 40%.

That came from the Redis layer. I also maintained the CI/CD pipelines and wrote the unit and integration test suites that every release went out behind.

Building for the next student.

PlaceIQ

Placement management for the officers who run it at Tier-2 and Tier-3 colleges. It started as a job-alert app for students; I reframed it as infrastructure for coordinators, because that is where the work piles up.

Many colleges share one system, so access is a four-tier hierarchy across 65 REST endpoints, with optimistic concurrency control so two coordinators cannot overwrite each other. Students get a resume builder with a live ATS score and a LaTeX mode; coordinators get Kanban tracking.

Resume scoring keeps model cost bounded: rule-based matching scores every submission, and the LLM review runs only on demand. 22 Jest and Supertest tests run in CI.

Other worlds I'm building.

What is on my desk right now: a game where language becomes magic, an experiment on how software agents remember, and the research questions underneath it. None of it is finished, and I'd rather show it as it is.

GameFounder

Arcanis

A competitive magic RPG that I am building as founder. You describe a spell in plain language, an LLM turns it into a balanced, classified spell with its own card art, and then players battle with the spells they wrote.

Spells are made in a Lab across a 12-element system. Battles are asynchronous PvP run by a rule-based engine, so a fight costs nothing in model calls. The hard part is fairness: anyone can type anything, and the game still has to stay balanced.

DevMem-Agents

My B.Tech minor project: an upgrade to the memory of Stanford's Generative Agents, the simulated town of Smallville. The flat memory stream is replaced by a four-stage developmental memory: personality priors, episodic memory, sleep-triggered consolidation, and identity. Everything else stays as upstream, so memory is the only variable.

I run it as project owner, with AI coding agents doing the implementation, under one hard constraint: zero API cost, using only free-tier keys rotated by a custom router. The baseline-versus-staged comparison is set up, and there are no results to report yet. The design is written up as an IEEE-format paper with two co-authors, presented in October 2026.

Research · none of it published yet
S-DAM
With Jaswanth Koppisetty
Decodable Is Not Usable: A Variance-Concentration Criterion for Core-Knowledge Priors in Associative Memory
We seed a Modern Hopfield memory with core-knowledge priors and test whether retrieval improves, on 6,000 CLEVR scenes encoded by a frozen DINOv2 ViT-S/14, with every threshold pre-registered before the runs. Object count is linearly decodable (R² = 0.95) yet carries only 1.03x the variance of a random direction, so decodability alone cannot qualify a memory prior. A factored-storage variant moved the retrieval crossover from 56% to 82% corruption: a partial fix, and reported as one.
